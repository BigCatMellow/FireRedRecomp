## Predicates and text

* `Cmd_typecalc` skips Struggle entirely; otherwise `GET_MOVE_TYPE` reads dynamic type when present, applies STAB and type rows, then if defender ability 25, `AttacksThisTurn()==2`, original **record power !=0**, and no net super-effective flag (or both super and resisted bits), sets `MISSED`, `B_MSG_AVOIDED_DMG` and clears last-landed bookkeeping (`pret/src/battle_script_commands.c:1274-1342`; `pret/include/battle.h:467-472`). `AttacksThisTurn` returns 1 only on a charging turn of listed two-turn effects, with the Solar Beam sun exception (`pret/src/battle_script_commands.c:7846-7863`). Use immutable record power, not a modified dynamic copy: Present/Hidden Power power 1 still qualify; effect power 0 does not. Struggle bypasses this command's check even if super/immune.
* `ModulateDmgByType` cancels opposing effectiveness bits on neutral dual-type combinations and removes super/resist on type immunity (`pret/src/battle_script_commands.c:1240-1271`). Thus net 2x/4x passes; 1x (including 2x×0.5x), 0.5x/0.25x and 0x block. Source immunity also sets DOESNT_AFFECT; Wonder Guard then sets MISSED and its miss type. `Cmd_resultmessage` chooses ability text because avoided-damage ID 3 exceeds avoided-attack ID 2, even with DOESNT_AFFECT (`pret/include/constants/battle_string_ids.h:415-418`, `pret/src/battle_script_commands.c:1930-1940`). It is incorrect to emit ordinary no-effect text for this overlap.
* `Cmd_typecalc2` reads the **record's static type** (not GET_MOVE_TYPE), ORs distinct super/resist bits, and on a type-zero row sets global DOESNT_AFFECT and immediately breaks its chart-order scan before its Wonder Guard predicate (`pret/src/battle_script_commands.c:4346-4436`). Its local flags are distinct from global result flags; do not globally equate them or assume an existing protected/missed result suppresses the ability branch. It similarly sets MISSED and ability miss reason, and leaves targetNotAffected tied to actual DOESNT_AFFECT. Rollout/Ice Ball use this route; Counter/Mirror Coat source scripts do too, but are unrepresented and outside this leaf. The currently shared `BattleFormulas.typeCalc` calculates final effectiveness; a scoped typecalc2 path must preserve source control/result ordering and static typing.
* On an ordinary random **accuracy failure**, `Cmd_accuracycheck` first sets MISSED, then `CheckWonderGuardAndLevitate` scans GET_MOVE_TYPE and overwrites miss reason for Wonder Guard when attack is non-super-effective (`pret/src/battle_script_commands.c:1092-1104,1345-1417`); the latter does not set MISSED itself. Its scan continues through the entire chart, independently ORing super/resist indicators even after setting global DOESNT_AFFECT for a zero row. Wonder Guard replaces the reason only when the local resist bit is present or the local super bit is absent. A zero combined with a super-only row leaves the ordinary miss reason and the immunity text wins. A zero without a super row, or a zero combined with both super and resist, does select the Wonder Guard reason. Protect and semi-invulnerability early exits precede this scan (`:945-1000,1020-1043`); scripts which explicitly run `typecalc`/`typecalc2` after such exits are exceptions below. Evaluate miss-helper at real call sites; do not invoke it on every false `hit`.
* Hidden Power is calculated before accuracy using IVs (`local/src/core/BattleEngine.lua:2210-2231`; `pret/src/battle_script_commands.c:8520-8527`); on ordinary typecalc/miss-helper use dynamic type and original record power. Weather Ball also uses dynamic type in these paths. Typecalc2 uses base type. Preserve V4a's no-fire-defrost behavior and unrelated AI prediction inputs.

## Three scan oracles (source chart order is authoritative)

Use original nonzero move power, attacking turn, Wonder Guard and no Foresight. Random-miss column assumes the ordinary accuracy roll fails. `pret/src/battle_main.c:330-335` orders the Electric chart Water-super, Electric-resist, Grass-resist, Ground-zero, Flying-super, Dragon-resist; defender type slot order does not reorder the chart. Each row takes zero target HP.

| Electric/Fire attack and target | Normal typecalc | Random-miss helper | Static typecalc2 |
|---|---|---|---|
| Electric vs Water + Ground | Ability reason 3 + immunity | Full scan finds super, no resist; ordinary miss reason, immunity text | Water-super then Ground-zero break: no ability reason, immunity text |
| Electric vs Ground + Flying | Ability reason 3 + immunity | Full scan finds super, no resist; ordinary miss reason, immunity text | Ground-zero breaks before Flying-super: ability reason 3 + immunity |
| Electric vs Ground + Ground | Ability reason 3 + immunity | No local super: ability reason 3 + immunity | First Ground-zero break: ability reason 3 + immunity |
| Fire vs Water + Grass | Net-neutral flags, ability reason 3 | Super and resist OR bits, ability reason 3 | Super and resist OR bits, ability reason 3 |

Tests must distinguish global result flags from each helper's local flags and assert reason/visible message, not damage alone. For normal typecalc a zero row clears global super/resist and global NO_EFFECT prevents later super/resist updates (`pret/src/battle_script_commands.c:1240-1271`). For typecalc2, the `!(flags & MOVE_RESULT_NO_EFFECT)` condition checks the *local* OR flags, which contain only effectiveness bits; it does not test existing global MISSED/DOESNT_AFFECT (`:4346-4436`). This is not a generic net-effectiveness predicate.

## Pinned acceptance: literal RNG and scope

Scripted no-ROM RNG traces assume no items, other random producers, first-battle overrides or unrelated start/end-turn draws; counts are move-resolution draws and include the newly blocked source tail when reached:

- Present heal: accuracy + Present choice = **2**; no crit/damage draw; no HP change with regained-health message. Full HP has the same two draws and full-HP message.
- Rollout on an ordinary landed or failed accuracy roll: **1**; protect: **0**. Both reach typecalc2 and blocked lock cancellation before crit/damage draws.
- Fury Cutter landed accuracy + crit = **2**, no damage-random; ordinary failed accuracy = **1**, no crit, both reset counter.
- First neutral Wonder Guard-blocked Triple Kick: accuracy + crit + damage-random + source `seteffectwithchance` tail = **4**. Its pre-damage presentation counter and cleared MISSED produce the source count despite zero HP change.
- Explosion: crit + damage-random + accuracy = **3** on ordinary check, or **2** under protect. It still self-faints; assert the separately established reason precedence.
- A blocked fixed-damage attack uses ordinary accuracy + hit-animation `seteffectwithchance` tail = **2**; blocked OHKO uses NO_ACC check then tail = **1**, without the OHKO roll. Psywave uses accuracy + rejection-sampled value + tail: **3** draws if the first value is accepted, or **3+r** if r rejected values precede it (`pret/src/battle_script_commands.c:7557-7565`). For example, a successful accuracy roll followed by samples `11, 15, 10` and the tail consumes **5** total draws. Assert both immediate acceptance and this rejection sequence; preserve the existing rejection helper and unblocked RNG. Include the pre-existing limitations of the generic unblocked code as controls, and never infer these counts for protection/semi-invulnerable branches that exit earlier.

The implementation task must include regression assertions for source-tail draws on each newly blocked represented route, normal unaffected controls, no unintended broad random-stream changes, and no source-parity claim for Counter/Mirror Coat/Bide fallback rows. Correct source/UI output is required, so narrowly scoped controller result handling is included in the candidate surface. There is no refusal approximation for represented routes.
