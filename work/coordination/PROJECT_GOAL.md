## Accepted instruction

Advance BigCatMellow/FireRedRecomp through its existing roadmap to independently
verified 1.0 readiness. Keep working across tasks and resumed sessions until
the roadmap's applicable exit gates are evidenced: clean verified-ROM import
and first run; faithful native FireRed US v1.0 gameplay; normal new-game-to-
credits progression; offline postgame completion; required battle, map, script,
menu, save, and presentation checks; and the agreed import/play/mod/update/
diagnose/save-recovery experience. Credits is an intermediate milestone.
Completion requires an independent final audit of those gates, with no known
crash, save-corruption, or progression-softlock defect. Unresolved required
evidence or human decisions remain blockers, never waived completion criteria.

Act as Orchestrator and own the next-step decision. I explicitly authorize
delegating bounded work to Worker agents and separate independent Reviewer
agents. Keep one behavior-changing package active at a time; use parallel
research only when boundaries and dependencies are demonstrably independent.
Do not require me to select routine next tasks, transfer role handoffs, or
repeat "continue" after each report, review, commit, or task closure.

At each resume, recover live GitHub state, inspect local changes and in-flight
jobs, and read AGENTS.md, the canonical capability checklist, the active task,
STATE.json, HANDOFF.md, TASK_REGISTER.md, relevant exact reviews, the execution
map, and the delivery plan. Use the repository's authority order. Reconcile
stale routing claims against accepted evidence; preserve user changes and
unreviewed drafts. Resume the actual next unfinished action. Do not restart
accepted work, treat old queued jobs as current, or infer task completion from
code or a Worker claim.

Run the complete relay autonomously: select the smallest unmet eligible gate;
compile a bounded task using the existing template when needed; obtain source
discovery, design, authority review, route readiness, and implementation
evidence as required by that task; assign the Worker; obtain independent
review of the exact revision; route the smallest correction after NEEDS_FIX;
and reconcile only the scope proven by PASS. Then select and begin the next
eligible package. Writing READY_FOR_WORKER or READY_FOR_REVIEWER is a handoff
to execute, not the end of the overall goal. A package stop condition ends that
package's actions; it does not prevent separately scoped discovery or eligible
independent work. Never widen the stopped package implicitly.

Follow canonical dispatch order and verified dependencies. Preserve current
accepted selections. At milestone closure, reassess what blocks the next
playable checkpoint. Rank further battle work by story need, represented
prerequisites, and testability, and develop P5/P6/P7 progression when its
prerequisites permit. Keep the full Phase 4 matrix open until proved. Use P0
reproducibility and P2 reference work when their required inputs are available;
an external blocker in one gate must not idle unrelated eligible work. Do not
generate speculative tasks or repeated planning documents just to remain busy.

Use the existing publication authority for task-bounded commits and pushes.
Honor task allowlists, exact route/probe/request gates, retry limits, and
independent review. Run required focused, regression, verified-ROM and replay
checks through the authorized environment; retain exact receipts and label
missing evidence honestly. Inspect existing jobs before any new submission.
Source uncertainty goes to bounded discovery rather than invented behavior.

Maintain a durable checkpoint in the existing coordination files after each
material transition and before a pause or handoff: current revision/worktree,
task and role, completed evidence and review verdict, pending changes and jobs,
remaining acceptance items, blocker and owner, and one exact next action with
its prerequisite. Update the task register, state, and handoff in that order;
update derived roadmap routing when dependencies change. Advance canonical
capability status only with independently verified exit evidence. Keep old
history separate from current instructions. Never mark this goal complete
because one task finished, a budget ended, or an input is missing.

Preserve the player-supplied-ROM model, supported revision, and all accepted
task exclusions. Keep ROMs, BIOS, private paths, extracted content, generated
caches, private screenshots, and secrets out of public artifacts. Remain within
the existing FireRed scope. New platform promises, public mod API scope,
credentials, purchases, signing, store submissions, and release publication
remain human decisions. Prepare concrete options and finish unaffected work
before escalating such a decision. Existing review gates cannot be bypassed.

When blocked, record the exact failed prerequisite and minimum unblock input;
check whether another existing eligible package can advance the roadmap.
Monitor authorized running jobs with the available wait mechanism and useful
status updates. Avoid repeated unchanged probes or exhausted retries. If no
authorized useful work remains, checkpoint and follow the goal system's
blocked-state rules. On resume, recheck the condition and continue from the
checkpoint. Respect user pauses and system budgets; do not invent a budget.

First action: freshly verify the starting state, reconcile the evidenced stale
coordination/routing fields, then execute the current effect-45 design and
independent review. Any route or implementation continuation requires its own
bounded task and required review; the design dispatch alone is insufficient.
Keep the quarantined Brick Break drafts preserved and outside active dispatch
unless a later evidence-backed selection explicitly supersedes the current one.

## Resumption

In the existing goal thread, `/goal resume` resumes a paused goal. A new
thread must be explicitly instructed to adopt this standing goal and recover
the live repository checkpoint. Do not depend on a temporary checkout path or
old chat context. The activated goal carries no user-specified token budget.
